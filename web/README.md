# Bailoteca web

Angular 22 SPA with Tailwind CSS 4 that consumes the Bailoteca public read-only
API. The site is prerendered at build time with `@angular/ssr` in
`outputMode: "static"`, so Vercel serves plain HTML files and no Angular server
runs at runtime. It does not include NgRx and has no database access: everything
goes through the public endpoints.

## Stack

- Angular 22 with standalone components, signals and lazy routes.
- Tailwind CSS 4 (CSS-first configuration, no `tailwind.config.js`).
- Vitest 5 with `jsdom` for unit tests.
- TypeScript 6.

## Structure

```text
web/
├── scripts/write-env.mjs             # generates environment.production.ts before the build
├── scripts/write-sitemap.mjs         # writes sitemap.xml and robots.txt after the build
├── public/                           # favicon, app icons, og-image.png and self-hosted fonts
├── src/
│   ├── environments/                 # development and production
│   ├── main.server.ts                # server entry used only at build time
│   ├── server.ts                     # Express entry generated by @angular/ssr (unused in static mode)
│   └── app/
│       ├── app.routes.server.ts      # prerender rules per route
│       ├── core/                     # API_BASE_URL token, models, HTTP client, error messages, SeoService
│       ├── shared/components/        # EmptyState, ErrorState, LoadingGrid
│       └── features/academies/
│           ├── academy-list/         # list with filters and pagination
│           ├── academy-detail/       # detail by slug, related academies
│           ├── academy-display.ts    # labels, maps, comunas, JSON-LD helpers
│           ├── academy-query.ts      # URL normalization
│           └── components/           # AcademyCard, FilterBar, Pagination, StyleBadges
└── vercel.json
```

## Requirements

- Node.js 24
- npm 11
- The API running (on `http://localhost:8000` by default)

## Development

```bash
cd web
npm install
npm start
```

The app runs at `http://localhost:4200` and reads `API_BASE_URL` from
`src/environments/environment.ts` (`http://localhost:8000` by default).

## Tests

```bash
cd web
npm test -- --watch=false
```

The tests use `HttpTestingController` and fixtures; they do not need the real
API.

## Production build

```bash
cd web
API_BASE_URL=https://api.example.com npm run build
```

`API_BASE_URL` is required: the `prebuild` script (`scripts/write-env.mjs`)
fails when it is missing and writes `src/environments/environment.production.ts`
before compiling. The build also queries the API (`/academies`) to prerender
every academy detail page, so it needs network access and a reachable
`API_BASE_URL`; if the API fails, the build fails instead of publishing an
incomplete site.

The output goes to `dist/bailoteca-web/browser/`, with one `index.html` per
prerendered route. The `postbuild` script (`scripts/write-sitemap.mjs`) reads
`dist/bailoteca-web/prerendered-routes.json` and writes `sitemap.xml` and
`robots.txt` next to the HTML. It also reads `updated_at` from the API to add
`<lastmod>`; if the API is unreachable at that point the sitemap is written
without dates. `SITE_URL` overrides the default `https://bailoteca.vercel.app`
used for absolute URLs.

## SEO

- **Prerender**: `/`, `/acerca` and every `/academias/:slug` are rendered to
  static HTML at build time; unknown paths fall back to the SPA.
- **About**: `/acerca` explains the directory and its methodology, names the
  maintainer and publishes `AboutPage` + `Person` schema with email, location
  and GitHub/LinkedIn profiles. The footer links to it from every page.
- **Meta**: `SeoService` writes title, description, canonical, robots, Open
  Graph and Twitter tags per page. Filtered and paginated list URLs are
  `noindex, follow`.
- **Structured data**: `DanceSchool` with address, `sameAs`, `telephone`,
  `geo`, `hasMap`, `aggregateRating` and `openingHoursSpecification` when the
  API has the data, plus `BreadcrumbList` on details. The home page publishes
  `WebSite` with `SearchAction` and `publisher`, and `Organization` with name,
  URL and logo.
- **Social image**: `public/og-image.png` (1200×630) is used on every page.
- **Internal linking**: detail pages list up to four academies from the same
  comuna, falling back to the same style. Pagination renders real `<a>` links
  with `rel="prev"`/`rel="next"` and keeps the active filters, so crawlers can
  reach every page of the list even though those URLs are `noindex`.
- **AI discovery**: `public/llms.txt` describes the directory and links to the
  home page, the sitemap and the public API. `robots.txt` explicitly allows
  GPTBot, ChatGPT-User, ClaudeBot, PerplexityBot, Google-Extended,
  Applebot-Extended, CCBot, anthropic-ai, Bytespider, FacebookBot and Amazonbot.
- **IndexNow**: production builds ping `api.indexnow.org` with every URL from
  the sitemap, so Bing and Yandex learn about new pages right after a deploy.
  The key lives in `public/<key>.txt`; preview and CI builds skip the ping.
- **Fonts**: Bricolage Grotesque and Instrument Sans are self-hosted in
  `public/fonts/` and preloaded; there is no request to Google Fonts.
- **Caching**: `vercel.json` sets `s-maxage=600, stale-while-revalidate=86400`
  for the home page and detail pages.
- **Security headers**: `vercel.json` sets `X-Content-Type-Options`,
  `X-Frame-Options`, `Referrer-Policy`, `Permissions-Policy` and a CSP. The CSP
  allows `'unsafe-inline'` scripts because Angular's prerendered event-replay
  bootstrap is inline, and `connect-src`/`img-src` allow HTTPS so a deployment
  can point `API_BASE_URL` at another host. Scripts stay limited to the site
  origin.

## Variables

| Variable       | Where                          | Use                                   |
| -------------- | ------------------------------ | ------------------------------------- |
| `API_BASE_URL` | build environment / `.env`     | Base URL of the public API            |
| `SITE_URL`     | build environment (optional)   | Absolute origin for `sitemap.xml`     |

There are no secrets in the browser. `web/.env.example` documents
`API_BASE_URL` and the optional `SITE_URL`.

## Endpoints consumed

| Method | Endpoint             | Use                                    |
| ------ | -------------------- | -------------------------------------- |
| `GET`  | `/academies`         | List with `comuna`, `style`, `q`, `page`, `page_size` |
| `GET`  | `/academies/{slug}`  | Academy detail                         |
| `GET`  | `/styles`            | Style filter options                   |
| `GET`  | `/comunas`           | Comuna filter options                  |

The client lives in `src/app/core/services/academies-api.ts` and only performs
reads.

## Routes

| Route              | Page                                       |
| ------------------ | ------------------------------------------ |
| `/`                | List with filters, search and pagination   |
| `/academias/:slug` | Academy detail                             |

Both are loaded with `loadComponent` (lazy). An unknown route redirects to `/`.
`src/app/app.routes.server.ts` prerenders `/` and every `/academias/:slug`
returned by the API; the catch-all renders in the client.

## Decisions

- **The URL is the list state**: `comuna`, `style`, `q` and `page` live in query
  params. Search is debounced 300 ms and rewrites the URL with `replaceUrl`, so
  the back button does not store every keystroke.
- **No `status` filter in the client**: every academy the API returns is shown;
  closed ones carry the "Cerrada" badge; the detail shows "Ficha revisada el <fecha>" from `verified_at` (or "Aún sin revisar") instead of a verification badge.
- **Internal data hidden**: `confidence`, `evidence`, `source_url` and
  `source_urls` are not rendered. Only public data is shown.
- **Invalid input is normalized**: styles with an invalid format, one-character
  searches and out-of-range pages are corrected in the URL.
- **Card links keep the filters** so you return to the same list.

## Deploying to Vercel

1. Create a project with **Root Directory** `web/`.
2. Build command: `npm run build`.
3. Output directory: `dist/bailoteca-web/browser` (the Angular preset detects it
   automatically).
4. Set `API_BASE_URL` to the public API URL in the project environment
   variables.
5. `vercel.json` rewrites every route to `index.html` so the Angular router
   works on reload. Prerendered routes are served as real files first, so the
   rewrite only handles unknown paths. It also sets the `Cache-Control` header
   for the home page and detail pages.

The API must allow the site origin in `CORS_ORIGINS`
(`https://<project>.vercel.app`). The `.github/workflows/web.yml` CI runs tests
and the build against the public API when `web/**` changes.

Production site: <https://bailoteca.vercel.app>, with
`API_BASE_URL=https://bailoteca-api.vercel.app`.
